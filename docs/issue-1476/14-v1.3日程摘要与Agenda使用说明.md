# Calendar v1.3：日程摘要与 Agenda 使用说明

v1.3 提供“业务受控”的日程展示能力：Calendar 负责告诉业务当前 42 格可见日期范围，业务负责加载并回填事件。组件不会内置 HTTP、鉴权、缓存或服务端状态，因此可复用于任何状态管理方案。

## 1. 事件模型

少量固定日程点可直接在组件 DSL 内声明：

```kotlin
Calendar {
    attr {
        events {
            event("review-2026-09", CalendarDate(2026, 9, 8)) {
                title = "设计评审"
                color = 0xFF8B5CF6
                extra("projectId", "calendar")
            }
            event {
                id = "release-2026-09"
                during(CalendarDate(2026, 9, 15), CalendarDate(2026, 9, 17))
                title = "版本发布窗口"
                color = 0xFFF97316
            }
        }
    }
}
```

`event(id, date) { }` 是最简的单日写法；`event(id, startDate, endDate) { }` 用于跨日事件。完整声明时以 `on(date)` 或 `during(start, end)` 设置日期，避免漏填 `startDate`。动态或服务端日程仍建议转换为 `List<CalendarEventSummary>` 后调用 `calendar.setEvents(result)`。

若 Calendar 和 Agenda 需要共用一组固定数据，可在视图外构建：

```kotlin
val launchEvents = calendarEvents {
    event("kickoff", CalendarDate(2026, 9, 4)) { title = "项目启动会" }
    event("release", CalendarDate(2026, 9, 15), CalendarDate(2026, 9, 17)) {
        title = "版本发布窗口"
    }
}
```

```kotlin
CalendarEventSummary(
    id = "release-2026-09",
    startDate = CalendarDate(2026, 9, 15),
    endDate = CalendarDate(2026, 9, 17), // 省略时等于 startDate
    title = "版本发布窗口",
    color = 0xFFF97316,
    type = "release",
    isAllDay = true,
    extra = mapOf("projectId" to "calendar")
)
```

`id` 不能为空，`endDate` 不能早于 `startDate`。跨天事件会在覆盖的每个日期格内出现；Calendar 仅为当前可见 42 格建立索引，不会把多年事件全量展开。

## 2. 受控加载

```kotlin
Calendar {
    attr {
        events = pageState.events
        eventDisplayMode = CalendarEventDisplayMode.DOTS
    }
    event {
        visibleRangeChanged { range ->
            viewModel.loadEvents(range.start, range.end)
        }
    }
}
```

首次创建、用户切月以及点击相邻月日期进入新月份时，`visibleRangeChanged` 会派发 `CalendarVisibleRange`。同一月份、相同首日设置下的范围会自动去重。`range.start` 与 `range.end` 包含相邻月补位日期，方便一次请求完整的 6×7 网格。

业务拿到新结果后可采用以下任一种方式回填：

```kotlin
calendar.setEvents(result)  // 推荐：复制列表、重建可见范围索引并刷新

// 或在自行替换 attr.events 后：
calendar.refreshEvents()
```

快速切月时应由业务以请求序号、协程取消或当前 range 校验防止旧响应覆盖新范围；组件刻意不管理网络生命周期。

## 3. 日期格标记模式

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| `DOTS`（默认） | 日期下方显示一个低干扰彩点，只提示当天有日程 | 移动端日程概览 |
| `COUNT_BADGE` | 日期下方居中的小圆点显示当天事件数量 | 待办、预约、工单 |
| `CUSTOM` | 不绘制默认事件视觉 | 由 `slots.marker` 根据 `CalendarDayState.events` 完全接管 |

当 `events` 非空时它优先于兼容的 `markers`；没有事件时仍按 v1.0 规则渲染 `CalendarMarker`。自定义 marker Slot 可以同时读取 `state.marker` 与 `state.events`，因此旧标记和新日程可平滑共存。

未选中日期不绘制背景。默认选中日期采用 `42 x 42` 的轻量蓝色圆角方形，日程以农历下方的单个彩点承载；文字区会自动为彩点预留底部空间，且彩点不会越出选中区域。可通过 `dayIndicatorSize` 和 `dayIndicatorCornerRadius` 调整选中态；`COUNT_BADGE` 的尺寸可由 `eventBadgeSize` 调整。常规月视图推荐保持 `DOTS`。

## 4. 农历与补充文案

基础组件不内置地区数据；农历、节气、节假日和调休由业务通过 `CalendarSupplementaryProvider` 接入：

```kotlin
Calendar {
    attr {
        showSupplementaryLabel = true
        supplementaryProvider = object : CalendarSupplementaryProvider {
            override fun supplementaryLabel(date: CalendarDate): String? {
                return lunarService.labelOf(date) // 例如 初一、春节、休
            }
        }
    }
}
```

补充文案会显示在日期数字下方，并进入 `CalendarDayState.supplementaryLabel` 供自定义插槽读取。默认选中态会把日期数字缩小为 `dayWithSupplementaryFontSize`，补充文案使用 `supplementaryFontSize`；有日程点时，两行文字会自动上移并收在 `dayIndicatorSize` 的圆角方形范围内。

## 5. CalendarAgenda 联动

`CalendarAgenda` 是独立组件，避免把列表、空态和点击行为塞进基础月历。它接收 `selection` 与 `events`，范围/多选默认取第一个自然日筛选。

```kotlin
private var agenda: CalendarAgendaView? = null

Calendar {
    attr { events = pageState.events }
    event {
        selectionChanged { selection ->
            agenda?.setSelection(selection)
        }
    }
}

CalendarAgenda {
    agenda = this
    attr {
        selection = CalendarSelection.None
        events = pageState.events
        emptyText = "当天暂无日程"
    }
    event {
        eventClick { summary -> openDetail(summary.id, summary.extra) }
    }
}
```

后续业务更新事件列表时，同时调用 `calendar.setEvents(events)` 与 `agenda.setEvents(events)` 即可。Agenda 提供 `eventContent`、`emptyContent` 插槽以及 `eventClick` 回调；点击事件会原样返回 `id`、`type` 和 `extra`。

## 6. 当前边界与后续演进

- 已实现：本地/受控事件、跨天裁剪、可见范围去重、DOTS 单点提示、数量角标、自定义标记、农历/补充文案 Provider、Agenda。
- 未实现：组件内部网络数据源、加载/错误状态机、跨天横条（BAR）、事件拖拽、周/日视图。
- `BAR` 需要按周行处理连续事件与重叠分层，属于后续独立迭代，不能用普通绝对定位替代。

演示页 `calendar_demo` 的“日程摘要与 Agenda 联动”覆盖彩点日程、跨天事件、可见范围回调、选日联动和日程点击回调。
