# Calendar 功能探索与演进方案

> 文档目的：在已完成 Issue #1476 基础月历的前提下，系统规划后续可迭代能力。本文是产品、API 与技术设计草案，不代表这些能力已经实现。

## 1. 当前基线

当前 `Calendar` 已提供：

- 单月 6×7 稳定网格、前后月切换、周起始日与中文星期标题。
- 单日期选择、今日态、禁用日期、最小/最大日期边界。
- 日期/月份回调、相邻月显示、多色事件圆点、主题、`dayContent` 内容插槽。
- Android 与 Kotlin/JS 编译校验，日期算法单测。

这套基础能力适合表单选日、预约入口、签到、活动页和轻量日程概览。后续能力应遵循三个原则：

1. **日期内核和业务事件分层**：月历只负责日期状态与渲染；课程、会议、价格、库存等由业务数据源提供。
2. **新增而非破坏**：不改变已有 `CalendarDate`、`dateSelected` 和单选默认行为；所有新选择模式均通过新增类型启用。
3. **跨端优先**：业务逻辑坚持 `commonMain`，仅在手势、无障碍等必须依赖平台能力处增加适配层。

## 4. v1.1：选择能力

### 4.1 单选、范围、多选统一模型

不建议在 `CalendarAttr` 上不断增加 `enableRange`、`enableMultiple` 等布尔属性。建议新增明确的选择模式与状态类型：

```kotlin
sealed interface CalendarSelection {
    data object None : CalendarSelection
    data class Single(val date: CalendarDate) : CalendarSelection
    data class Range(val start: CalendarDate, val end: CalendarDate?) : CalendarSelection
    data class Multiple(val dates: Set<CalendarDate>) : CalendarSelection
}

enum class CalendarSelectionMode { NONE, SINGLE, RANGE, MULTIPLE }
```

建议属性与事件：

```kotlin
attr {
    selectionMode = CalendarSelectionMode.RANGE
    selection = CalendarSelection.Range(CalendarDate(2026, 8, 2), null)
    maxSelectionCount = 10                 // MULTIPLE 生效
    maxRangeDays = 31                       // RANGE 生效，0 表示不限
    rangeOverflowPolicy = RangeOverflowPolicy.RESTART
}
event {
    selectionChanged { selection -> }
    selectionRejected { reason, attemptedDate -> }
}
```

其中 `dateSelected` 保持可用；在 `SINGLE` 模式下它继续如现在一样调用。新业务优先使用 `selectionChanged`，以接收所有模式下的统一结果。

### 4.2 范围选择交互

1. 首次点击有效日期，设置 `Range(start, null)`，起始日期显示实心圆。
2. 第二次点击晚于或等于起始日期，形成闭合区间；中间日期显示连续浅色底。
3. 若第二次点击早于起始日期，默认从该日期重新开始；可通过 `rangeOverflowPolicy` 配为自动交换。
4. 点击禁用日期、范围外日期或跨越禁用日期时不改变选择，并派发 `selectionRejected`。
5. `maxRangeDays` 超出时不自动截断，以免用户误认为选择成功；应显示业务提示或派发拒绝原因。

### 4.3 多选交互

- 每次点击切换某日期的选中状态；禁用日期不能加入集合。
- 达到 `maxSelectionCount` 后，默认拒绝新增而不移除旧值；也可提供 `MultipleOverflowPolicy.REPLACE_OLDEST`。
- 标题区域可显示“已选 3 天”，但应通过 Header Slot 让业务自行决定文案。

### 4.4 验收标准

- 范围跨月仍正确渲染左右端点和中间段。
- 边界、禁用日期与业务谓词在三种选择模式下行为一致。
- 程序性 `select()` 应升级为 `setSelection(selection, emitEvent = false)`；不产生重复业务回调。
- 连续区间必须处理一周首尾、相邻月日期及 42 格网格边缘，不出现断裂。

## 5. v1.2：可定制、快速导航与可访问性

### 5.1 插槽体系

当前只有 `dayContent`，建议扩展为分组插槽：

```kotlin
class CalendarSlots {
    var header: CalendarHeaderSlot? = null
    var headerTitle: CalendarHeaderTitleSlot? = null
    var headerLeading: CalendarHeaderActionSlot? = null
    var headerTrailing: CalendarHeaderActionSlot? = null
    var weekday: CalendarWeekdaySlot? = null
    var dayContent: CalendarDayContent? = null
    var marker: CalendarMarkerSlot? = null
    var footer: CalendarFooterSlot? = null
    var emptyContent: CalendarSimpleSlot? = null
}
```

优先级固定为：**完整 Header Slot > Header 子 Slot > 默认 Header**；**dayContent > 默认日数字与 marker**。所有 Slot 均接收不可变状态对象，不能直接改变组件内部状态；状态改变必须调用公开 action，例如 `actions.showMonth()` 与 `actions.select()`。

### 5.2 年月快速跳转

适用于出生日期、远期预约和历史查询。建议提供两种模式：

- `CalendarMonthPicker`：从日历标题点击打开年月面板，先选年再选月。
- `CalendarYearPicker`：适合一次显示多年网格，可按区间虚拟化。

```kotlin
attr {
    monthPickerEnabled = true
    yearRange = 1970..2100
    yearPickerStep = 12
}
event {
    monthPickerVisibilityChanged { visible -> }
}
```

注意：`yearRange` 只限制导航，不等价于可选日期；日期是否可选仍由 `minDate/maxDate` 与业务谓词统一判定。

### 5.3 回到今天

已有 `showToday()` 命令，v1.2 只需补充可选 UI：当可见月份不等于今日所属月份时显示“回到今天”按钮。

```kotlin
attr {
    showTodayAction = true
    todayActionText = "回到今天"
}
event {
    todayActionClick { }
}
```

业务可用 Footer Slot 替换其视觉样式；组件只负责可见状态与月份跳转。

### 5.4 无障碍与键盘

目标是让 H5、Android、iOS 用户能理解并操作日期网格：

- 每个日期生成语义文案，例如“2026 年 7 月 15 日，今天，有 2 项日程，已选中”。
- 禁用日期必须声明不可操作，而非只改变颜色。
- 焦点移动：左右箭头移动一天，上下移动一周，PageUp/PageDown 切月，Enter 选择。
- 月份改变后将焦点保持在同一日；若目标月没有该日，定位到月末。

此项依赖 Kuikly 的跨端语义/键盘事件能力。若框架尚无统一接口，应先设计 `CalendarAccessibilityAdapter`，不能在 `commonMain` 中伪造平台实现。

## 6. v1.3：事件数据、标记与日程联动

### 6.1 从 Marker 升级为事件摘要

`CalendarMarker` 适合轻量提示，却无法表达数量、优先级、全天/跨天事件。建议保留旧类型并新增可选事件模型：

```kotlin
data class CalendarEventSummary(
    val id: String,
    val startDate: CalendarDate,
    val endDate: CalendarDate = startDate,
    val title: String = "",
    val color: Long = 0xFF4F8FFF,
    val type: String = "default",
    val isAllDay: Boolean = true,
    val extra: Map<String, String> = emptyMap()
)

interface CalendarEventSource {
    fun load(rangeStart: CalendarDate, rangeEnd: CalendarDate, callback: (CalendarLoadResult) -> Unit)
}
```

组件仅保存与渲染可见范围内的摘要，不管理服务器缓存、鉴权或事件详情。

### 6.2 本地与远程数据源

| 模式 | 接口 | 适用场景 | 注意事项 |
| --- | --- | --- | --- |
| 本地 | `events: List<CalendarEventSummary>` | 小型活动页、静态假期 | 列表变化需使用响应式集合或显式 refresh |
| 远程 | `eventSource.load(rangeStart, rangeEnd)` | 企业日程、预约库存 | 需去重、取消过期请求、缓存已加载月 |
| 受控 | `onVisibleRangeChanged` 由业务回填 `events` | 已有状态管理框架 | 组件不持有网络逻辑，最易测试 |

建议优先受控模式：

```kotlin
attr { eventDisplayMode = EventDisplayMode.DOTS }
event {
    visibleRangeChanged { start, end -> viewModel.loadCalendarEvents(start, end) }
    eventClick { event -> }
}
```

`visibleRangeChanged` 必须在首次渲染和每次月份改变时触发，并带去重策略：相同范围、相同筛选条件不可重复请求。

### 6.3 标记渲染模式

```kotlin
enum class EventDisplayMode {
    DOTS,          // 最多三点，超过后显示 +N
    COUNT_BADGE,   // 数量角标
    BAR,           // 跨天事件横条，适合范围事件
    TEXT,          // 单行标题，适合桌面宽布局
    CUSTOM
}
```

- `DOTS`：移动端默认，空间最省。
- `COUNT_BADGE`：适合待办、预约数量。
- `BAR`：需要周行内连续布局与碰撞分层，技术成本显著增加。
- `TEXT`：必须限制行数，并保留“更多”入口。
- `CUSTOM`：业务通过 `marker` Slot 完全接管视觉。

### 6.4 日程列表联动

月历不应直接承担复杂列表。建议提供独立 `CalendarAgenda` 组合组件，二者通过同一 `CalendarSelection` 或受控状态连接：

```kotlin
Calendar { event { selectionChanged { ctx.selection = it } } }
CalendarAgenda(
    selection = { ctx.selection },
    eventSource = { ctx.events }
) {
    event { eventClick { event -> } }
}
```

当用户点击日期：月历更新选择 → Agenda 按该自然日筛选 → 展示空态、加载态或事件列表。保持组件分离可以让表单场景不引入列表成本。

### 6.5 验收标准

- 连续跨月事件在各月正确裁剪，不越出月格边界。
- 远程请求快速切月时，旧响应不能覆盖新月份数据。
- 同日超过三类事件时展示统一 `+N` 规则，并提供完整语义文本。
- 事件点击返回原始 `id` 与 `extra`，不丢失业务字段。

## 7. v1.4：多月浏览与视图模式

### 7.1 滑动切月

先实现横向一屏一月，而不是立即实现无限流：

- 拖拽距离或速度超过阈值才切月，避免纵向列表滚动误触。
- 动画期间锁定新触摸，防止重复切月。
- 到达 `minDate/maxDate` 所在月时阻尼回弹，而不是出现空白月。
- 触发顺序：`monthWillChange`（可选）→ 动画 → `monthChanged` → `visibleRangeChanged`。

需要增加：

```kotlin
attr {
    monthChangeGestureEnabled = true
    monthChangeAnimationDuration = 220
    monthSwipeThreshold = 0.25f
}
```

### 7.2 纵向无限月历与虚拟化

当业务需要浏览数十年时才启用。核心不是“无限”，而是只保留可见区域附近的月份：

- 维护窗口：当前可见月前后各 2～4 月；窗口大小可配置。
- 使用 `CalendarMonth` 索引计算，而非预生成全部日期。
- 滚动后回收离屏月份，保留选择状态与加载缓存。
- 当用户跳到某月时调用 `scrollToMonth(month, animate)`。

```kotlin
attr {
    layoutMode = CalendarLayoutMode.VERTICAL_PAGED
    overscanMonthCount = 3
}
```

该能力应建立在 Kuikly `List`/虚拟列表的跨端表现验证完成后再实现；不可简单用 `Scroller` 无限叠加月份。

### 7.3 周视图、日视图

| 视图 | 内容 | 适用 | 依赖 |
| --- | --- | --- | --- |
| 月视图 | 6×7 日期格 | 选日、概览 | 已实现 |
| 周视图 | 7 天横排 | 轻量排班、健康记录 | 周切换、同一天聚焦 |
| 日视图 | 小时网格与全天栏 | 会议、课程、预约 | 事件时间、冲突布局、滚动定位 |

建议 `CalendarView` 只发展到月/周；日视图应作为独立 `ScheduleView`，否则基础日历包会被事件排版和时间轴逻辑拖重。

## 8. v2.0：中国化与专业排期

### 8.1 农历、节假日与调休

农历不是简单增加一个文字字段，涉及历法转换、节气、节假日版本、地区差异和年度数据更新。推荐可插拔设计：

```kotlin
interface CalendarLocaleProvider {
    fun weekdayLabels(firstDayOfWeek: CalendarWeekday): List<String>
    fun monthTitle(month: CalendarMonth): String
    fun supplementaryLabel(date: CalendarDate): String? // 例如 初一、春节、休
    fun isHoliday(date: CalendarDate): Boolean
    fun isWorkdayOverride(date: CalendarDate): Boolean
}
```

基础包默认只提供公历中文/英文 Provider。中国节假日和农历数据应单独发包，并明确支持年度与数据来源，防止组件升级被节假日规则绑架。

### 8.2 重复事件

重复规则属于事件层，建议兼容 iCalendar 常见语义：daily、weekly、monthly、yearly、interval、until、count、exceptions。不要在每个日期格上实时展开所有多年事件；应由数据源在可见范围内计算实例。

### 8.3 拖拽改期

适合排班/项目管理，不适合默认月历。建议先作为实验性 `CalendarDragDrop` 扩展：

- 长按事件进入拖拽，目标日期显示可放置态。
- 释放时只派发 `eventMoveRequested(event, targetDate)`，由业务确认并更新数据源。
- 网络失败时业务回滚，组件不直接修改远程数据。
- 无障碍模式必须保留“移动到日期”替代操作。

## 9. 性能、可靠性与测试要求

### 9.1 性能约束

- 单月模式维持固定 42 个日期单元格；切月只更新该窗口。
- `markers/events` 按日期索引为 `Map<CalendarDate, List<...>>`，避免每个单元格遍历全量事件。
- 高成本 Slot 由业务负责缓存；组件应记录 Slot 调用边界。
- 无限模式必须提供 `overscanMonthCount`，默认不超过 3。

### 9.2 日期与时区

- UI 层持续使用 `CalendarDate`（自然日），不直接使用 UTC 时间戳。
- 事件若有时间，需要定义“展示时区”；服务端时间戳应在数据源层转换为自然日。
- 跨日、夏令时、全日事件需要在事件数据层测试，不能由月格算法隐式处理。

### 9.3 自动化测试矩阵

| 类别 | 必测场景 |
| --- | --- |
| 公历算法 | 闰年、世纪年、月首周日、跨年、最小/最大日期 |
| 选择 | 单选、范围正/反向、多选上限、禁用日期、跨月选择 |
| 事件 | 空/加载/错误、慢请求回写、跨月事件、超过三项标记 |
| 手势 | 阈值不足、快速滑动、边界回弹、动画中重复手势 |
| 跨端 | Android/iOS/鸿蒙/H5 截图金标：月首、月末、深色主题、中文/英文、长标题 |
| 无障碍 | 读屏文案、焦点顺序、键盘选日、禁用态语义 |

## 10. 建议的实施顺序与拆分

1. **独立 PR/版本 1：选择模型**：只做 `CalendarSelection`、范围/多选、连续背景、测试和 Demo。
2. **独立 PR/版本 2：插槽与导航**：补 Slot、年月面板、回到今天；不耦合网络事件。
3. **独立 PR/版本 3：事件源**：先受控 `visibleRangeChanged + events`，稳定后再提供 `CalendarEventSource`。
4. **独立 PR/版本 4：手势与虚拟化**：先横滑单月，验证四端后再做纵向无限。
5. **可选插件**：农历节假日、重复事件、拖拽改期、日程时间轴。

这种拆分可保证基础 `Calendar` 始终轻量、可测试，并降低跨端问题的定位成本。

## 11. 决策清单

进入下一阶段前，建议先确认：

- 范围选择是否允许跨越不可选日期？默认建议不允许。
- 多选达到上限时是拒绝、替换最早还是替换最新？默认建议拒绝。
- 事件是否由组件拉取网络数据？默认建议业务受控回填。
- 是否将农历作为核心依赖？默认建议可选插件。
- 滑动切月是否需要与页面横向手势协调？需要先确认 Kuikly 容器的手势竞争策略。
- 是否有无障碍语义和键盘事件的框架级 API？没有则将该项排入框架协作需求。
